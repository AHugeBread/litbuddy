# litbuddy v2.2.0 · 使用说明

> 这是一套**可迁移、自包含**的科研入门级文献管理系统 —— **litbuddy**（中文名：**面包图书馆**）。
>
> 它把"读文献"从"零散地读"变成一条**可重复、可检索、可交接、可产出**的流水线：自动归类入库、在库中智能检索、生成文献翻译与知识精讲、汇总每日科研简报，并提供了一整套与 agent 协作的 SOP。你可以就文献中的任意知识、思路或背景提问，也能在新一天的工作开始前收到一份包含上一个周期全部思考的科研简报，还可以双击内置的文献检索程序，用关键词快速定位库内的文献……
>
> **总而言之：litbuddy 就是你的智能文献管理系统。** 把下载好的新文献复制到 `_收件箱\`，在 agent 对话窗口里随意发问 —— 开启你的 litbuddy 科研之旅吧。

## 一、初次使用
<a id="S001"></a>

litbuddy 有两种获取方式，**最终得到的文献库完全一样**，只是起步步骤不同：

| | 方式 A · 开放平台 skill | 方式 B · 完全发行包 |
|---|---|---|
| 适合 | 已在使用 WorkBuddy，想直接装技能 | 想要一个下载即用的完整文件夹 |
| 文献库根目录 | 初始化引导时**由你选定/新建** | 发行包文件夹本身就是根 |
| 起步 | 见下方 A-1～A-3 | 见下方 B-1～B-4 |

### 方式 A · 开放平台 skill（技能名 `breads-litbuddy`）

#### A-1 · 安装技能

在 WorkBuddy 的开放平台/skillhub 搜索安装 `breads-litbuddy`（面包图书馆）。

#### A-2 · 发起首次配置

在任意工作空间里对 agent 说一句：

> 我要初始化 litbuddy 文献库。

agent 会引导你**选定或新建一个专用文件夹**作为文献库根（请选长期位置，例如 `D:\我的文献库\`，**不要**用桌面、下载目录或 Agent 默认目录），确认后自动把六层结构、模板与工具展开到该根，并把根路径记入该库的 `00-AI协作规范\_状态.md`。

> ⚠️ 如果你指定的文件夹里**已有散落的文献**，它们**不会被自动搬动**——agent 会列出清单，由你自己决定哪些移进 `_收件箱\`。

#### A-3 · 之后，工作空间指向你的文献库根

以后使用时，在 Agent 中新建对话时，把工作空间设为**你选定的根文件夹**，然后继续看下方「之后日常只有三件事」。

### 方式 B · 完全发行包

#### B-1 · 解压后放到一个长期位置

把 litbuddy 文件夹解压到**你希望长期存放的位置**（例如 `D:\我的文献库\`）。

- 它就是你的**文献库本体**，之后所有内容都长在这里 —— 所以**不要**放在桌面、下载目录这类临时位置。
- 也不需要"安装"：整个文件夹复制走就能用。

#### B-2 · 把新文献丢进 `_收件箱\`

下载到的任何 PDF / 规格书 / 专利 / 笔记，**先一律丢进去**。

#### B-3 · 让工作空间指向本文件夹

在 Agent 里新建项目，工作空间选**本文件夹**。

> ⚠️ 这一步是必须的：agent 靠"当前工作空间"来定位文献库。选错会找不到 `_收件箱\`。

#### B-4 · 把下面这段话发给 agent

> 本工作空间是 litbuddy（一套科研文献管理系统，技能名 `breads-litbuddy`），本文件夹就是我的文献库根目录。
> 请按顺序做三件事：
>
> ① 环境自检（分侧）：先检查库根结构是否完整（`01-原始文献\`、`_收件箱\`、`02-加工与沉淀\`、`03-每日简报\`）、技能是否就位、`tools\build_search.py` 是否存在、Python 是否可用、目录是否可写；再报告只有你能检查的项（本机是否已有 litbuddy 相关定时任务、连接器状态），并明确告诉我哪些项需要我人工确认。任何一项不通过，先停下告诉我，不要继续。
> ② 读技能内 `SKILL.md` 熟悉路由与铁律 —— 只读它，其他 references 用到哪篇读哪篇，不要盲目遍历全部文件；然后按技能内 `references\01-收件箱分派.md`，把 `_收件箱\` 里我已经放好的文献走完整入库流水线：分派归类 → 英文文献出翻译 → 更新初印象卡 → 重跑检索索引，四步在同一轮连着做完。
> ③ 首次使用还有两件小事：生成检索程序 `python tools\build_search.py`；把 `00-AI协作规范\_状态.md` 里的 `水位线` 改成今天，作为简报起点。
>
> 边界：中文文献只建初印象卡、不做自动加工；判不准的进"待你决定"清单不要猜；改名和删除必须先问我。

### 之后日常只有三件事

| 想做什么 | 怎么做 |
|---|---|
| **提问** | 直接在对话里问（概念、思路、"为什么必须这样"） |
| **检索** | 精确找某个词 → 双击库根下的 `打开文献检索.html`；描述一个意思 → 让 agent 在库内智能检索 |
| **加文献** | 继续丢 `_收件箱\`，让 agent 走入库流水线 |

> 检索程序生成一次即可。**只有"生成它"和"重建索引"需要 Python；日常双击使用不需要。**

## 二、litbuddy 功能说明
<a id="S002"></a>

### 1. 收件箱分派

新文献丢进 `_收件箱\` → agent 自动**判层、去重、归档**，并按目录规范落位。

- **触发**：对话触发
- **可自动**：分类移动

### 2. 初印象卡

每篇文献一段 100–300 字的粗读点评 + 库内相关文献，构成文献库的**轻量目录**。共 **4 份**（国内 / 国外 / 厂商 / 总览）。

### 3. 三级检索系统

| 级别 | 用什么 | 解决什么 | 成本 |
|---|---|---|---|
| **① 本地字段匹配** | 双击 `打开文献检索.html` | "我知道要找**哪个词**" —— 精确字符定位 | 零成本、离线 |
| **② 库内智能检索** | 对 agent 描述你想找什么 | "我**记不清怎么表述**，但能描述我要什么" —— 库内模糊 / 语义查找 | 占用一定上下文 |
| **③ 对外查找新文献** | 让 agent 去外部数据库检索 | "库里**确实没有**" —— 检索新文献、核验题录、取合法全文 | 联网搜索，较费token |

### 4. 每日简报

以**第一人称"我"**的口吻，记录上一个周期里我读了什么、聊了什么、得出什么结论 —— 是**你的科研日志**。

- 可以通过 **[三、高级配置 1.配置每日自动化]** 将简报触发方式改为定时任务触发。

- **不是每天都有** —— 科研不是每天都发生；隔了几天没对话，一篇简报覆盖整个区间。

### 5. 文献学习

五个子功能，覆盖"从读到懂"的全过程（读文献统一按**四问**思考：研究背景 → 旧法为何失效 → 本文做了什么 → **本文没做什么**——最后一问直指潜在创新点）：

| 子功能 | 做什么 | 触发方式 |
|---|---|---|
| **外文文献翻译** | 段落**中英对照** + 术语表 + 锚点索引 + 原文关键词 + **原文插图提取**（图嵌入 + 双语图注） | 随入库自动（**仅英文文献**） |
| **文献问答** | 就某篇文献提问（概念、思路、"为什么必须这样"），按"工程背景 → 为何此前失效 → 设计哲学 → 系统定位 → 取舍 → 演化"作答，收尾带"未解决与未提及"视角 | **你主动提问** |
| **文献总结** | 对**单篇文献**的通盘理解（黑箱理解 / 逐节笔记等），落 `2-文献总结\` | **你主动要求**（入库自动总结暂未启用） |
| **知识精讲** | 把讨论过、想明白了的概念沉淀成**可脱离原文独立阅读**的讲解（**不写页码**；插图分"原文提取/自绘"两种图源） | **半自动**：答完主动问一句要不要存 |
| **文献串讲** | 把**多篇（≥2）**文献连成**技术路线演化网**（承接 / 并行竞争 / 并行互补，**带页码溯源**），落 `5-文献串讲\` | 你主动要求 |

### 6. 系统功能

| 功能 | 做什么 |
|---|---|
| **版本更新** | 升新版时**你的数据**完整保留，**旧版原样不动**；支持**原地更新**（当前库直接升）与**跨文件夹收编**（旧发行包文件夹迁入新库）；（详见「四、版本更新」） |
| **项目状态清单** | `00-AI协作规范\_状态.md` 一处集中存放系统要判定的状态（水位线 / 简报触发方式 / 画像是否问过 / 协作规范版本 / 库的部署形态与根路径等）。用户可以通过修改此清单中的状态值快速修改skill配置 |
| **使用者画像** | 文献满 5 篇时 agent **主动问一次**（四个问题），据此在 `00-AI协作规范\` 生成你的特化文档，让后续回答更对口（问过与否记在 `画像询问` 键，详见「一、初次使用」末段） |
| **反馈留档** | agent 在使用中发现 litbuddy 的问题或值得学习的好做法，自动记到 `tools\反馈\`（**仅本地**，详见「五、反馈与数据说明」） |
| **项目记忆** | 跨会话记住你的协作口径与项目背景 |
| **外部进度同步** | 把你在 **litbuddy 之外**讨论的进展并入库：agent 读完后写进当日 memory，**每日简报自动覆盖**（详见「7. 外部进度同步」） |

### 7. 外部进度同步

你在其他 Agent 上的讨论也是科研进展，但发生在 litbuddy 之外。本功能让外部进展安全并入。

**用法两步**：

1. **与外部Agent讨论收尾时**，把下面这段提示词复制发给你的外部 AI，它会按约定格式生成一份"进度同步文档"：

> 我们这次讨论结束后，请生成一份"litbuddy 进度同步文档"，严格遵守以下格式，不要增删栏目：
>
> ```
> # 进度同步 · <用一句话概括本次讨论主题>
>
> > 本文档性质：litbuddy 外部进度同步
> > 生成方：<你的名称与版本>　|　日期：<今天>　|　供：导入 litbuddy 文献库
>
> ## 已达成的理解
> <我们讨论后形成的判断与结论，逐条，忠于讨论内容、不要添加我们没有讨论过的东西>
>
> ## 未解疑问
> <我们尚未定论的问题，逐条>
>
> ## 待验证线索
> <你提出、但提醒我们未经本地文献或实验核验的论断，逐条标注>
>
> ## 附随产物
> <本次讨论中产生、值得搬运进文献库的文件（代码、图、串讲稿等）：逐个写"文件名 + 一句话说明 + 建议入库层级"。
>  注意主 agent 无法自行取回文件，需要我手动复制——所以这里列的要确实值得搬。没有则写"无">
>
> ## 建议下一步
> <建议我在文献库里继续做的事：查哪篇文献、核验哪条线索、问哪个问题>
> ```
>
> 生成后我会把它发回我的 litbuddy 库，那边的 agent 会按格式吸收。

2. **拿到文档后**，把它丢进 `_收件箱\`（或在对话中上传引用/直接粘贴要点）——agent 会识别为外部同步，按技能内 `references\18-外部进度同步规范.md` 的流程处理。

## 三、高级配置
<a id="S003"></a>
> 本节全部为**可选**配置。不配置也能正常使用 litbuddy。

### 1. 创建每日自动化

如果你希望每日简报**到点自动生成**，可以改成 WorkBuddy 定时任务触发。

> ⚠️ **只针对「每日简报」，不针对收件箱分派。**

#### 一键配置模板

把下面这段整体发给 agent：

> 本工作空间是 **litbuddy**（技能名 `breads-litbuddy`），**本文件夹就是我的文献库根**。
> 我要把**每日简报**从「对话触发」改为「**定时自动化触发**」。请按顺序执行：
>
> ① **先做环境自检（分侧）**：确认库根结构完整、技能就位、`tools\build_search.py` 存在、Python 可用、`00-AI协作规范\_状态.md` 可写；并检查本机是否已有同用途的定时任务。**任何一项不通过就停下告诉我，不要继续。**
> ② 自检通过后，创建一个**每天 21:00（北京时间）**执行的自动化任务：
>    - **工作空间设为「本文件夹」**（务必确认，否则会写到默认的 `automation-xxxx` 目录）；
>    - **提示词**：`本轮由 WorkBuddy 定时任务实际触发。读取技能内 references\09-每日简报规范.md，按其「定时任务实际调用」场景执行：检查 00-AI协作规范\_状态.md 里的水位线键，按规范生成本周期科研简报，并原子推进水位线。`
> ③ 任务创建成功后，把 `00-AI协作规范\_状态.md` 的 `简报触发` 键由 `对话` 改为 `自动`（整文件读-改-写，别只改一行就丢）。
> ④ 告诉我创建结果，以及如何退回对话触发。
> - ⚠️ **① 和 ② 都成功，才允许做 ③。** 任一步失败都**不要**改 `简报触发` 键。

#### 回退（改回对话触发）

把下面这段发给 agent：

> 我要把每日简报**改回「对话触发」**。请：① 删除我本机那条每日简报定时任务；② 把 `00-AI协作规范\_状态.md` 的 `简报触发` 键改回 `对话`。两步都做完后告诉我结果。

### 2. Max模式

把 `00-AI协作规范\_状态.md` 里的 `Max模式` 键设为 `开`（老库无此键即为默认模式），即把整个 litbuddy 的协作档位从**低成本性价比**切到**较高成本、更精准**——这是全局开关，一键生效，不需要逐功能配置：

- **知识精讲**：三遍绑定式自检（数值独立验证 / 结构审查 / 规范核查）
- **文献问答**：对话内轻量一遍自检
- **文献串讲**：对照表与关系判定复核

## 四、版本更新
<a id="S004"></a>
> **适用**：你已经在用旧版 litbuddy（**v1.1.1 及以后**），现在拿到了新版。
>

### 路线一 · 原地更新（v2.0.0 起，推荐）
<a id="S00401"></a>

适合：**当前这个库就是要升级的库**，且你的 skill 已是新版（开放平台升级，或发行包内嵌技能已刷新）。

1. 工作空间指向**你的文献库根**（就是现在这个库，不用新建文件夹）。
2. 对 agent 说：

> 本工作空间是 **litbuddy**（技能名 `breads-litbuddy`），**本文件夹就是我的文献库根**。
> 我要**升级 litbuddy 到新版**。请按技能内 `references\11-版本更新与迁移规范.md` 的**原地更新**流程执行，**先只出清单给我确认，不要动任何文件**。
> 铁律：我的内容一个都不能丢；判不准的列入"待你决定"，不要猜。

3. 审阅清单 → 回复「执行」→ agent 就地刷新系统文件（模板、说明、工具、版本号；被刷新的文件先备份到 `99-临时文件\_更新备份-*\`）→ 看回执与 `99-临时文件\_更新日志-*.md` → 运行 `python tools\build_search.py` 重建检索程序。

> 原地更新**不搬动你的任何数据**。

### 路线二 · 跨文件夹迁移（旧发行包迁入新库）
<a id="S00402"></a>

适合：你手里是一个**旧版发行包文件夹**（v1.1.1–v1.4.x），要把数据迁进一个新库。

1. **把新版文件夹放到任意位置** —— **不要**放进旧版文件夹内部，也不要和旧版互相包含。
2. 在 WorkBuddy 里新建项目，工作空间选**新版文件夹**。
3. 把下面这段话发给 agent（把尖括号处换成你自己的旧版路径）：

> 本工作空间是 **litbuddy**（技能名 `breads-litbuddy`），**本文件夹就是我的文献库根**。
> 我要**从旧版更新**：旧版 litbuddy 文件夹是 `<把这里换成旧版文件夹的完整路径>`。
> 请按技能内 `references\11-版本更新与迁移规范.md` 执行，**先只出迁移清单给我确认，不要动任何文件**。
> 铁律：旧版目录只读不写；我的内容一个都不能丢；判不准的列入"待你决定"，不要猜。

4. 审阅清单 → 回复「执行」→ agent 搬运 → 看回执与 `99-临时文件\_更新日志-*.md` → 运行 `python tools\build_search.py` 重建检索程序。

### 更新之后

- **只在新版里工作**，旧版不要再动，否则两份会分叉。
- 旧版文件夹**系统不会删除** —— 它就是你随时能退回的备份。确认新版无误后，由你自己处置。

## 五、反馈与隐私说明
<a id="S005"></a>

litbuddy 有一个**反馈收集口**：`tools\反馈\`。

**做什么用**：使用过程中，agent 若发现 litbuddy 本身的问题或值得学习的好做法，会自动记一条进去 —— 例如"知识精讲模板里的举例不适配我的专业""某条规范走不通、只能靠猜""我想出的某条做法明显更好"。

**记在哪**：`tools\反馈\反馈记录.md`（累积式台账）；`tools\反馈\README.md` 是说明。

### ⚠️ 关于数据采集，你需要知道三件事

1. **它只存在你自己的电脑上。** agent 不会联网、不会上传、不会发送给任何人。
2. **你能完全控制它。** 打开 `反馈记录.md` 就能看、能改、能删；整份删掉也不影响 litbuddy 使用。每次协作收尾，agent 只会用**一行**告诉你"本次记了几条"。
3. **是否分享由你决定。** 只有当**你自己**把 `反馈记录.md` 发给开发者时，它才会离开你的电脑。按规范，记录中**不含**你的文献正文、笔记正文、项目指标、绝对路径与用户名。

## 七、常见问题与解决方法
<a id="S007"></a>

| 现象 | 处理 |
|---|---|
| **skill 装好了，第一次怎么用** | 在任意工作空间对 agent 说「我要初始化 litbuddy 文献库」，按引导选定/新建库根即可（见「一、初次使用 · 方式 A」） |
| **发行包解压之后不知道做什么** | 见「一、初次使用 · 方式 B」四步；关键是 B-3 把工作空间指向本文件夹 |
| 没有 `打开文献检索.html` | 首次使用要生成一次：在库根下运行 `python tools\build_search.py` |
| 检索结果里的链接点不开 | 用**浏览器直接打开**库根下的 `打开文献检索.html`（双击）。从预览器打开时相对链接会失效 |
| 检索不到新加的文献 | 重跑索引：`python tools\build_search.py` |
| **库里明明有，但检索不到** | 一级检索是**机械字段匹配**，不能检索同义替换。你可以向agent直接发问：**用一段话描述你想找什么**，让 agent 做库内智能检索 |
| 技能没被触发 | 发行包：确认技能在 `.workbuddy\skills\breads-litbuddy\`，且工作空间指向的正是本文件夹；skill 安装：确认已在开放平台启用该技能 |
| 每日简报没生成 | 检查 `00-AI协作规范\_状态.md` 的 `水位线`；只有水位线之后有新对话才生成 |
| **改成自动化后，简报还是没生成** | ① 确认本机那条定时任务**存在且未被暂停**；② 确认触发时刻 WorkBuddy **客户端在运行**；③ 看 `_状态.md` 的 `简报触发` 是否为 `自动` |
| **画像问过了，但答得不准 / 想改** | 直接说一句「**改画像**」或「重新问我」，agent 会重问那四个问题并**更新**那份特化文档（不会新建第二份） |
| **不想被问画像** | 明确说"先不用"，agent 会把 `画像询问` 记成 `已拒绝 <日期>`、**此后不再问**；想用时再说「改画像」即可 |
| **把整个库文件夹搬了位置** | 照常使用即可；agent 发现 `_状态.md` 的 `项目根` 键与实际位置不符时，会提示你确认刷新（定时自动化任务需重建，见「三、高级配置」） |
| 拿到了新版，怎么升级 | 见「四、版本更新」：当前库直接升走路线一（原地更新），旧发行包迁入新库走路线二 |
| 更新后旧版怎么处理 | **只在新版里继续工作**；旧版留作备份，确认无误后由你自己删 —— 系统不会替你删 |
| 反馈文件我不想要 | 直接删掉 `tools\反馈\反馈记录.md` 即可，不影响任何功能；也可以用编辑器改掉不想留下的条目 |
| 改名了初印象卡，检索的卡片定位失效 | 卡片的文件名是**固定约定**（`01-原始文献\文献初印象卡（总览）.md` 等 4 份），改名会破坏检索解析。改回来，或问 agent |
