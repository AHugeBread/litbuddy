# 知识精讲 · 模板

> 使用前先读技能内 `references\08-知识精讲规范.md`。
> **四要素必写**：① 问题动机 ② 对照/取舍表 ③ 映射到本项目 ④ 下一步。
> **红线**：精讲**不带页码**（带页码说明写成了索引）。

---

## 通用抬头（三选一后接对应骨架）

```markdown
# <概念 / 板块名> · 知识精讲

> **主题**：<一句话说清这份精讲在讲什么>
> **粒度**：单概念深挖 ｜ 多概念对比 ｜ 框架级理解
> **来源**：讨论于 <日期>；触发文献（可选）：<F-0x / D-0x 简称>
> **关联**：<库内其他精讲或文献，编号 + 简称；没有就删掉此行>
```

---

## 骨架 A · 单概念深挖

适用：把**一个概念**讲透（如"功率反射""Q 值""镜像阻抗"）。

```markdown
# <概念> · 知识精讲

> 主题：… ｜ 粒度：单概念深挖 ｜ 来源：…

## 一、为什么需要它
<问题动机。先讲出现了什么工程问题、此前的方法为何不够用。**不从定义开始。**>

## 二、核心定义与公式
<一句话定义 + 关键公式。公式用纯文本写清符号含义。>

## 三、机制：它是怎么发生的
<物理过程 / 推导直觉。讲"为什么会有这个现象"。>

## 四、生活类比
<可选的，但强烈建议。用一个日常场景把机制说通。>

## 五、后果与代价
<这个现象/机制会带来什么问题。>

## 六、解决方案有哪几条路
| 路线 | 做法 | 优点 | 代价 | 失效条件 |
|---|---|---|---|---|

## 七、映射到本项目
<它在当前研究里处于什么位置、影响哪个模块（如 PA / 匹配网络 / 控制）。>

## 八、一句话总结
<一段话收尾。>

## 九、下一步
<接下来该做什么 / 该看哪一篇 / 该验证什么。>
```

## 骨架 B · 多概念对比

适用：把**一组方案/拓扑**并置比较（如"PA 拓扑""可变匹配方案"）。

```markdown
# <板块> · 知识精讲

> 主题：… ｜ 粒度：多概念对比 ｜ 来源：…

## 一、分类逻辑
<按什么维度分？为什么这样分？>

## 二、逐项展开

### 2.1 <方案 A>
- **结构**：…
- **原理**：…
- **优点**：…
- **缺点**：…
- **适用场景**：…

### 2.2 <方案 B>
（同上五段式，**格式必须一致**，便于横向对比）

## 三、对比表（横向一览）
| 方案 | 结构复杂度 | 效率 | 负载适应性 | 主要代价 | 适用场景 |
|---|---|---|---|---|---|

## 四、选择依据
<什么条件下选哪个。给出判定顺序，不要写"看情况"。>

## 五、映射到本项目
<针对本项目（约束现状见项目 `00-AI协作规范\`）该怎么选。>

## 六、下一步
```

## 骨架 C · 框架级理解

适用：建立**一整套递进框架**（如"分层理解模型"）。

```markdown
# <框架名> · 知识精讲

> 主题：… ｜ 粒度：框架级理解 ｜ 来源：…

> **方法**：从理想简化模型出发，逐层引入一个现实约束，每层回答"引入了什么新问题 + 如何解决"。

## 第 1 层：<场景>
### 场景
### 你需要做什么
### 这一层没有任何难度  ← 或：这一层的新问题
### 这一层新增的核心概念
| 概念 | 含义 |
|---|---|

## 第 2 层：<引入约束 X>
### 新问题
**问题 2.1**：…
**问题 2.2**：…
### 解决方案
### 这一层新增的核心概念
| 概念 | 含义 |
|---|---|

## …（逐层递进，每层只加一个现实约束）

## 总结：核心问题演化链
```text
第 1 层: …
   ↓ 加 <约束>
第 2 层: …
```

## 映射到本项目
| 子系统 | 涉及层级 | 核心难度 |
|---|---|---|

## 下一步
```

## 填写指引

| 检查项 | 标准 |
|---|---|
| 第一段是不是"问题动机"？ | 若不是，删掉重写 |
| 有没有对照/取舍表？ | 无 → 补一张 |
| 有没有写失效条件与代价？ | 无 → 补（**禁止写成普适最优**） |
| 有没有"映射到本项目"？ | 无 → 补 |
| 有没有"下一步"？ | 无 → 补 |
| 出现页码了吗？ | 出现 → 删掉（那是「文献串讲」的活） |
| 是不是从定义开始、堆术语？ | 是 → 重写为"为什么需要它" |
